# Migrating from 0.1.0 to 0.2.0

**Document ID:** PRIMITIVES-MIGRATION-020

**Schema version:** 1

**Kind:** guide

**Lifecycle:** current

**Subject:** how code that did arithmetic with points under 0.1.0 is rewritten for 0.2.0

**Surface:** migration

**Boundary:** primitives

**Authority role:** non-normative

**Mutation:** authored

**Indexing:** include

**Reference date:** 2026-10-12

0.2.0 separates the point (where something is) from the vector (how far and
which way it moves), and removes from the point what depends on where the
origin is ([PXL-ARCHIVE-008](../../../archive/release-0.2.0-2026-10-12.md)).
Code that only builds, compares, converts, or tests points, rectangles, and
colors needs no change; PixieInspector, for one, updated without any. Code that
does arithmetic with points stops compiling, on purpose, and is rewritten as
below. The current contract is the
[primitives reference](../REFERENCE.md) and the
[math reference](../../math/REFERENCE.md#points-and-vectors).

## The rewrites

| 0.1.0 | 0.2.0 | When |
|---|---|---|
| `(p + q) / 2` | `PxPoint.Lerp(p, q, 0.5)` | The midpoint; any weight in `t` |
| `p + q` | `p + (PxVec2)q` | `q` was really an offset: better, make it a `PxVec2` |
| `PxPoint d = p - q` | `PxVec2 d = p - q` | The difference is now a vector |
| `p * k`, `p / k` | `o + (p - o) * k` | Scaling about a reference point `o`, usually what was meant |
| `p * k`, `p / k` | `(PxPoint)((PxVec2)p * k)` | Exactly the old result, about (0, 0) |
| `-p` | `o - (p - o)` | Mirroring about `o`; `(PxPoint)(-(PxVec2)p)` about (0, 0) |
| `rect + p`, `rect - p` | `rect + (PxVec2)p` | Moving; putting it somewhere is setting `Location` |

In C++ the same, with `pxPoint::Lerp`, `pxToVec2(q)`, and `pxToPoint(v)` in
place of the casts. In C++, `p - q` and everything with a vector need
`<pixie/math/pxVec.hpp>` and the `pixie::math` target; without them,
`p - q` stops at a `static_assert` that says so.

## Example

```csharp
var p = new PxPoint(1, 2);
var q = new PxPoint(5, 6);
var o = new PxPoint(10, 10);
PxPoint mid = PxPoint.Lerp(p, q, 0.5);               // (3, 4)
PxVec2 d = p - q;                                    // (-4, -4)
PxPoint scaled = o + (p - o) * 2;                    // (-8, -6)
PxPoint scaledAtOrigin = (PxPoint)((PxVec2)p * 2);   // (2, 4), the old p * 2
PxRect shifted = new PxRect(0, 0, 4, 4) + (PxVec2)q; // (5, 6, 4, 4)
```

```cpp
#include <pixie/math/pxVec.hpp>

pxPoint p{ 1, 2 }, q{ 5, 6 }, o{ 10, 10 };
pxPoint mid = pxPoint::Lerp(p, q, 0.5);
pxVec2 d = p - q;
pxPoint scaled = o + (p - o) * 2.0;  // GLM's scalar is of the vector's type
pxPoint scaledAtOrigin = pxToPoint(pxToVec2(p) * 2.0);
pxRect shifted = pxRect(0, 0, 4, 4) + pxToVec2(q);
```

Both were compiled and run on 2026-10-12 against 0.2.0 and print the values in
the comments.

## What else is new

The point's `Lerp`, the integer `PxVec2i.Length()` and its siblings, `mat3 *
point`, and the segment are additions; they break nothing.
